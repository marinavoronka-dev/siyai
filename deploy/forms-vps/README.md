# Обработчик отзывов и заявок для AdminVPS

Независимый Node.js 18+ сервис на `127.0.0.1:3001`, без npm-пакетов. Старый сервис на 3000 и его файлы сохраняются. Код сайта не заменяется: установщик добавляет только совместимую генерацию UUID для HTTP.

Поддерживает:

- `GET /api/forms/challenge`, `POST /api/forms`: существующее приложение версии 38. Подписанный challenge привязан к клиенту, действует 20 минут, минимальная задержка 2.5 секунды, проверяется honeypot. Ответ содержит `success`, `stored`, `id`.
- `POST /api/contact`: HTML-сборщик, оценки 1–5 и текстовые ответы.
- `POST /api/lead`: HTML-сборщик, имя, контакт и заметка. Ответ legacy-формам содержит `ok: true` только после сохранения.

Данные: `/var/lib/siyai-forms/messages.jsonl`, вне каталога сайта, права 0600, каталог 0700. Запись синхронная, fsync выполняется до успешного ответа. Неполная последняя строка при запуске приводит к остановке с ошибкой, а не к тихому удалению данных. Один процесс. Файл должен резервироваться отдельно, с ограничением доступа; при большом количестве сообщений понадобится SQLite/PostgreSQL.

Идемпотентность основной формы сохраняется после перезапуска; legacy-формы с тем же содержимым от того же клиента не дублируются в пределах 10 минут. Лимиты: 5 новых сообщений за 10 минут, 20 в сутки на клиента, 500 в сутки всего; 60 запросов API в минуту на клиента. Сетевой адрес записывается только в виде HMAC. Origin проверяется по точному PUBLIC_ORIGIN. Это базовая защита от спама, не CAPTCHA; несколько людей в одной сети делят лимит.

Ни почта, ни Telegram автоматически не отправляются. Веб-кабинет автора из Cloudflare не переносится: платформенные заголовки авторизации не считаются доверенными. Публичного API чтения нет. Просмотр сохранённых сообщений только через SSH:

```bash
sudo /usr/bin/node /opt/siyai-forms/server.mjs --list
```

Команда выводит JSON по одному сообщению на строку. Не публикуйте этот вывод: там могут быть контакты и личные сообщения.

## Установка на проверенную конфигурацию VPS

Скачать `server.mjs`, `nginx.conf`, `install.sh` в один новый каталог. Выполнить в SSH-терминале сервера:

```bash
bash install.sh
```

Установщик рассчитан на существующие пути:

- `/etc/nginx/sites-enabled/sbor-otzyvov`
- `/var/www/siyai-main/dist/client/index.html`
- `server_name 185.219.43.207;`
- `PUBLIC_ORIGIN=http://185.219.43.207`

Нужны системный `/usr/bin/node` 18+, Nginx, Python 3, curl, systemd, пользователь www-data. Установщик ничего не устанавливает пакетным менеджером, не удаляет и не перезаписывает существующие файлы нового сервиса; повторный запуск останавливается для проверки. Не выполняет git pull, не заменяет сайт и не трогает сервис на 3000.

Перед изменениями проверяет конфигурацию и сохраняет Nginx/HTML в новый каталог `/var/backups/siyai-forms-*`. Генерирует случайный секрет только на VPS, создаёт сервис `siyai-forms`, добавляет include API в существующий server{} и проверяет Nginx перед reload. При ошибке nginx -t или reload восстанавливает Nginx/HTML. При других ошибках печатает шаг ошибки; резервная копия остаётся. Удаление каких-либо файлов не выполняется.

После установки обновите страницу Ctrl+F5, отправьте один пробный отзыв и проверьте его через `--list`. Не считайте локальные тесты доказательством работы на VPS. Ошибки: `systemctl status siyai-forms --no-pager` и `journalctl -u siyai-forms -n 30 --no-pager`; сообщения и секреты сервис в журнал не печатает.

Если открываете присланную форму через `/feedback/`, её абсолютные пути `/api/contact` и `/api/lead` обслуживаются тем же новым API. Основной интерфейс и сборщик работают через один origin, CORS не требуется.

Для перехода на HTTPS сначала подключите существующий сертификат в Nginx и проверьте сертификат без отключения проверки TLS, затем измените PUBLIC_ORIGIN на точный HTTPS-адрес в `/etc/siyai-forms.env` и выполните `systemctl restart siyai-forms`. Принимается только один настроенный origin. HTTP не шифрует содержимое сообщений.

## Откат

Установщик печатает точную команду с уникальным путём резервной копии: восстановить Nginx и HTML, проверить nginx -t, выполнить reload, затем `systemctl disable --now siyai-forms`. Данные остаются на диске; ничего не удаляется. Это отключает приём новых сообщений.

## Проверка разработки

```bash
node --check server.mjs
bash -n install.sh
node --test test.mjs
```

Интеграционный тест использует временный каталог и loopback-порт: основная форма, challenge, неподходящий Origin, подделка токена и заголовков автора, ограничение размера, конфликт и повтор ID, обе legacy-формы, лимит сообщений, права файла, восстановление после рестарта и отказ запуска на повреждённом журнале. Установка systemd/Nginx проверяется только на целевом VPS; локально проверен синтаксис shell и безопасная вставка конфигурации/UUID.
