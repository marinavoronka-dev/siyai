# Сияй! — приложение Марины Воронцовой

Привычки ухода, календарь, советы Мии и квесты. Первый этап — 21 день, следующие — 28. Отметки участниц остаются в браузере; отзывы и заявки сохраняются на сервере.

## Структура

- `web/` — интерфейс, картинки, стили, манифест и service worker.
- `server/worker.mjs` — публичный приём форм и защищённый кабинет автора.
- `server/author.html`, `server/author.js` — кабинет автора.
- `drizzle/0000_forms.sql` — схема D1, применяется при размещении.
- `scripts/build-server.mjs` — сборка Worker и файлов сайта в `dist/`.
- `tests/server.test.mjs` — проверки с настоящей локальной SQLite.

Нужен Node.js 22.13+ (для встроенной SQLite). `npm run build`, затем `npm run test:server`. Зависимости для сборки не нужны. Для локального выполнения Worker и D1 нужен Cloudflare Wrangler; статический HTTP-сервер не поддерживает отправку форм.

## Собственный приём форм

POST `/api/forms` сохраняет сообщение в D1. FormSubmit не используется. Отзыв не требует контактов; для заявок взрослых требуется только email для ответа. Адрес получателя не содержится в коде участниц. Уведомления по email пока не подключены; сообщений о почтовой доставке приложение не показывает.

Кабинет: `/author`. Вход через ChatGPT платформы Sites, без собственного пароля приложения. Первое связывание допускается только для подтверждённого платформой email автора из секретной настройки `AUTHOR_SETUP_EMAIL`. Затем доступ привязан к стабильному Site-specific user ID в D1 и не предоставляется другим пользователям с тем же email. Не допускайте подмену `oai-authenticated-*` заголовков при переносе на иной хостинг: там потребуется собственная проверенная авторизация.

Runtime-настройки задаются в Sites Settings, не в Git:

- `PUBLIC_ORIGIN` — точный HTTPS-адрес сайта;
- `FORMS_SIGNING_KEY` — секретный случайный ключ подписи;
- `AUTHOR_SETUP_EMAIL` — секретный email текущего владельца, только для первоначального связывания.

`.env.example` содержит только названия. Настоящие ключи, email настройки доступа и пароли нельзя коммитить. После успешного первого входа автора секрет первоначального email можно удалить; сохранённый user ID продолжит работать. Его смена или восстановление доступа требуют отдельной проверенной операции администратора, публичного сброса нет.

### Защита

Только same-origin JSON-запросы; размер тела ограничен; значения проверяются на сервере. Подписанный challenge привязан к хешу сетевого адреса, действует 20 минут и допускает отправку не ранее чем через 2.5 секунды. Есть honeypot и лимиты: 5 сообщений за 10 минут и 20 в день для одного сетевого адреса, 500 в день всего. Это базовая защита от спама, не полноценная CAPTCHA. Общая сеть может делить лимит между людьми. В production сетевой адрес должен поступать из доверенного `CF-Connecting-IP`, не из произвольного пользовательского заголовка.

Решение о приёме и запись выполняются атомарно. UUID повторной попытки с тем же содержимым не создаёт дубль. Черновик сохраняется в открытом окне при ошибке; успешный ответ появляется только после записи. IP в открытом виде не хранится: хеш и временные события ограничения удаляются через сутки при следующей отправке. Тексты сообщений остаются в базе до отдельной операции удаления автором. Не собирайте телефоны, адреса, школы и фото детей; регулярно пересматривайте необходимость хранения сообщений.

Кабинет показывает сообщения по категориям и допускает обратимую отметку прочитанного. Все сообщения выводятся текстом, не HTML. Его страницы и API имеют `Cache-Control: no-store`; service worker не кеширует их или отправку форм.

## Мобильная версия

Добавление на главный экран и кеш открытых материалов работают через HTTPS. Для форм нужен интернет. Автоматической синхронизации чек-листов между устройствами нет. Изменение серверных форм не отправляет письма и не создаёт новый почтовый ящик.
